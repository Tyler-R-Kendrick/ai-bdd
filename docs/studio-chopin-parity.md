# Chopin feature inventory

This inventory compares Studio source **`fe21dd4`** with the concrete published Chopin surfaces inspected on **2026-10-30**. It is a feature comparison, not a statement that a landing-page screenshot proves production acceptance. Rows name the implementation and checks; genuine missing software is listed explicitly rather than attributed to unavailable credentials.

Sources inspected:

- [GitHub Next project article](https://githubnext.com/projects/chopin/), including its seven headline features and the saved full-page capture `work/references/chopin.png`.
- [Chopin README](https://github.com/githubnext/chopin/blob/main/README.md), saved as `work/continuation/references/chopin.md` and `work/references/chopin.md` (300 lines).
- [Implementation lifecycle](https://github.com/githubnext/chopin/blob/main/docs/implementation-lifecycle.md), saved as `work/continuation/references/chopin-implementation-lifecycle.md` (graph, machine, verification and living-document details).
- [Local investigations](https://github.com/githubnext/chopin/blob/main/docs/local-experiments.md), saved as `work/continuation/references/chopin-local-experiments.md` (358 lines).
- [Agent connection](https://github.com/githubnext/chopin/blob/main/docs/agent-connection.md), saved as `work/continuation/references/chopin-agent-connection.md` (883 lines, including streaming, questions, run stages and backend launch).

The saved documents are research inputs in the shared workspace; the links above identify their public origins. They describe a changing research prototype. This audit uses the observed behavior, including the lifecycle documentation's explicit future-work boundaries, rather than inventing functions implied by the word “parity.”

**Status:** **Local** means implemented with the named local checks. **Different** means the same user capability uses a deliberate Studio contract, described in the row. **Gap G#** means confirmed missing software at this pinned source. The gap ledger names the implementation workflow; a fixture passing is never substituted for a gap being implemented. “External” names the particular live acceptance still required when the local implementation exists.

## Deployment and verification are separate acceptance dimensions

Studio intentionally extends beyond the single-writer reference: async SQLite/PostgreSQL adapters, shared SQL jobs/outbox, multi-instance Yjs merge, object/workspace storage ports, Vercel queue/scheduler composition and media Sandbox adapters are implemented. [Persistence](../packages/studio/tests/persistence.test.ts), [durable job PostgreSQL](../packages/studio/tests/durable-jobs-postgres.test.ts), distributed collaboration and hosting/media tests include real database, process-kill, actual SDK HTTP and real local OCI renderer checks. Those tests do not create a live Vercel account, an organization GitHub App approval, an installed user's ACP agent or a model subscription.

The existing [release browser receipt](studio-evidence/continuation/final-all-browser/README.md) identifies the exact source, commands, actual browser states and explicit local protocol fixtures. The broader non-Chopin requirements—Pact previews, code/UI/media canvases, Open Design, font/logo/icon tooling and bounded formal checks—are mapped in [architecture](studio-architecture.md) and [readiness](studio-readiness.md); they are not omitted Chopin capabilities or evidence for an untested live integration.
