# Living documents and existing-PR rebuilds

A successful, independently verified browser implementation establishes an immutable delivered source baseline when it has an open PR. The baseline keeps the exact original source, approved graph and implementation run. Editing its document then shows a count of added, removed or changed top-level blocks. Moving an otherwise unchanged identified block does not count as new content.

**Build changes** seals the latest document and resolves the original PR URLs through the requesting user's repository identity. Every PR must still be open in the same repository, with a valid head branch and full commit. It queues the rebuild on the person's own registered machine. The connector prepares isolated worktrees at those commits and the server checks the current heads again before execution. It instructs the ACP agent to update only those original branches using ordinary non-force pushes; quoted before/after documents are data, never new agent permissions.

A separate fresh ACP session independently inspects the rebuilt commits and reports every criterion of the approved base graph. The server verifies those exact current PR commits through the repository adapter, checks current access and deterministic document prerequisites, then atomically records the completed receipt and advances the source baseline. Rebuild receipts stay linked to the original approved graph: generated delta work does not silently create or approve a graph version. Reports are attributed external observations, distinct from Studio's own test runs.

The original builder may explicitly select **Let this machine rebuild this repository automatically**. Consent binds that user, machine and registered repository. Writer-persisted JSON, Yjs, MCP and reviewed proposal edits schedule SQL-backed checks after a five-second settle interval. Platform maintenance processes those checks; an in-memory timer is not the durability boundary. Only the original builder's currently authorized, connected and consented machine can receive automatic work. A newly unresolved human decision, discussion, suggestion or investigation remains a deterministic prerequisite. Model completeness advice cannot veto Build or grant approval.

Revoking consent fences active automatic work. Role, machine, account-device and repository authorization are checked again at claim, heartbeat, start and publication. One account device cannot claim overlapping work through separate project credentials. Ended leases fail with retained worktrees; uncertain agent side effects are never automatically repeated. **Retry changes** is a new explicit request against the latest document and PR heads. Edits made during an active rebuild remain pending after that rebuild completes.

Limits are explicit: one active rebuild per document, 20 original PRs, 1 MiB per source snapshot, 256 KiB per implementation/verifier receipt, 40 admissions per project per hour, and 256 MiB retained source history per project. Up to 100 run receipts per document are retained; older ended runs are pruned when new work is admitted. Export streams the retained credential-free baseline/history, source snapshots and receipts. Lease tokens, verifier credentials and other users' machine identities are excluded. The baseline remains even when old ended history is pruned.

`rebuild-machines.test.ts` covers real SQLite and PostgreSQL lifecycle, snapshots, consent, source/head fences, verification, retry and revocation. Its standalone-connector case builds the distributable, runs real ACP/MCP sessions and actual Git worktrees/branch compare-and-set while preserving a dirty operator checkout. PR identity is a local HTTP protocol fixture in that test, not a live GitHub PR. Hosted providers, account consent, production scheduling and a real repository still require deployed acceptance.
