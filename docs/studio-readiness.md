## Deployment state

The replaceable production composition uses PostgreSQL for canonical state and fences, private object storage for assets/evidence/workspaces, and durable job/outbox/queue/scheduler ports. SQLite and disk remain documented local single-writer adapters. PostgreSQL multi-instance tests do not establish production capacity, high availability or multi-region operation. The separate [isolated Neon preflight](studio-evidence/continuation/neon-preflight/README.md) applied the actual 72-table schema, verified suspension durability and restored synthetic source/ADR/chat/revision records by resetting a disposable child to its test parent. Native TCP/App HTTP was unavailable in this workspace; the receipt is provider SQL/branch-reset evidence, not PITR, object recovery or a production restore rehearsal.

The Vercel project `ai-bdd-studio` is linked to `Tyler-R-Kendrick/ai-bdd` and configured for Node 24. An isolated Neon production database has been created and queried on PostgreSQL 17.11. The user authorized deployment and the exact team/private repository. A fresh nonsecret production environment write still returns provider HTTP 403: additional permissions are required to create production environment variables. Private Blob creation is also denied. This is missing connected-app write access, not missing user consent. The permission update or dashboard bindings remain pending. The source-context fix produced a real `READY` preview at `98ffeb2` and published the backend image; [the receipt](studio-evidence/continuation/vercel-preview-build.md) records the actual digest. Public root/health/readiness requests return 302 to Vercel SSO, so application health remains unverified. **No production Studio release, bound Blob store, deployed queue execution or live model turn has been verified.** Credentials are not recorded here.

The hosted composition is a stateless container with external durable state. Trusted deployment metadata supplies preview origins; production requires an exact canonical origin. Queue/cron bridges authenticate internal requests; SQL intents preserve recovery across process loss. A dispatch acknowledgement is not completion, and external provider/coding effects are not claimed to execute exactly once.

Hosted media now has a real `@vercel/sandbox` 3.9.1 adapter and a locally exercised OCI worker: twelve checks and fifteen completed protocol requests cover all five audio formats, MP4/WebM, inspection, expected invalid-source rejection, tamper rejection and cancellation; fifteen requests does not mean fifteen successful exports. [Media runtime evidence](studio-media-runtime.md) distinguishes the local image config ID from an immutable registry manifest digest. A registered private image, production binding and actual hosted Sandbox VM have not been verified.

T3 is the default generative harness. Without an operator-registered trusted binary, project and authenticated provider, it reports unavailable. Vercel/fx requires explicit selection and configuration. Decision models have a separate profile and provider boundary. Local HTTP fixtures and actual T3 version/help checks do not establish successful paid-provider inference.
