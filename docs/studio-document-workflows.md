# Collaborative document workflows

The document workflow keeps authoring, review, decisions, and evidence on one artifact. These are implemented application behaviors, not assertions of a live model/provider deployment.

The source audit used the [Chopin project page](https://githubnext.com/projects/chopin/) and [current public README](https://github.com/githubnext/chopin/blob/main/README.md), inspected on 2026-10-29. The README identifies a restricted MDX editor, persistent attributed decisions, inline child research, repository admission, and agent collaboration. Repository authorization, agent execution, machine pairing, and background-worker behavior are covered by their respective integration workflows; the document layer does not substitute a local rendering for those services.

## Interchange boundaries

Markdown text imports are limited to 1 MB. DOCX input is limited to 10 MB, 256 ZIP entries, 16 MB expanded content, and 8 MB per entry. ZIP64, encrypted/multi-disk archives, unsafe or repeated paths, inconsistent directory counts, DTDs, and external entities are refused. XML parsing has no network or filesystem resolver. ZIP comments are normalized before inflation so embedded directory markers do not redirect the ZIP reader. Parsing runs in a worker with cancellation and a 15-second timeout.

Imported embedded PNG/JPEG assets are uploaded through the ordinary artifact permission/quota boundary only after the user reviews the import. External Word image relationships are not fetched. Markdown images outside the project's uploaded-file namespace remain descriptive links; imports cannot manufacture access to another project's files. Import requires an unchanged opening document and its expected revision, so a teammate's intervening edit causes a conflict instead of being replaced.

Word exports retain supported prose, formula source, common formatting, lists, table geometry, and embedded raster images. Interactive planning widgets become readable prose in Word and HTML; restricted MDX and fenced Studio blocks preserve their editable data. Word tracked-change history is imported as final text with an explicit warning. Nested Word list indentation is flattened with a warning. Macros, arbitrary React modules, external templates, and full Word layout/review compatibility are not part of this interchange format. Artifact discussions, review history, and ADRs remain in the application and the full project export rather than being falsely represented as native Word metadata.

Source-evidence cards identify the source artifact/version. A passing child scenario does not certify the parent document. Unlinked, missing, interrupted, failed, or stale evidence never becomes a passing criterion through presentation alone.
