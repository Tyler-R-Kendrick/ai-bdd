# Conversation offers

The optional conversation workflow is enabled only when the operator passes `enabled: true` to `registerConversationRoutes`; the default is off. It uses an independently selected Decision Model for finite eligibility and the explicitly selected agent harness/provider/model for proposal writing through the installed AI SDK. The default T3 harness is never silently replaced by Vercel/fx. Both profiles freeze in the durable job at admission; changing either picker affects a new analysis, not an already admitted request.

The service captures one artifact/thread, its exact version and content hash, the latest twelve messages (1,800 characters each, explicitly marked when truncated, with hashes of the full bodies), and up to forty accepted decision identities/versions. It persists this immutable snapshot and a durable job/outbox together. Rapid new messages make an older snapshot stale before generation. The model receives no unrelated artifact thread and no provider credentials in the snapshot.

A receipt-backed native decision step asks one boolean eligibility question. Only an answered true result permits proposal writing. Answered false, abstention, refusal, provider error, probability, and reported confidence remain distinct in the persisted result and UI; no prose is generated for those non-true outcomes. Provider/model identity and the independent decision evaluation ID remain visible. Eligibility input respects the selected provider byte budget, including Jev’s 32,000-byte limit; shortened or omitted context is explicitly marked and the complete source snapshot/hash remains unchanged for publication guards.

A second receipt-backed external step asks the frozen selected generative harness for at most four fixed-schema offers. Every cited message must exist in the snapshot, and the displayed source quotation must be a verbatim substring of a cited message. Final publication checks artifact access, version, and discussion hash again under the durable runtime's project/job locks. Provider requests are at least once before a receipt persists; the stable key is supplied to providers supporting idempotency. A 60-second model timeout and two durable attempts bound one analysis. A writer can explicitly retry failed, cancelled, or no-offer analysis, up to ten generations per source snapshot. A changed profile permits a fresh analysis of unchanged discussion. Automatic observation skips an unavailable generative harness without preventing a human chat message from saving; explicit analysis reports the configuration error.

Writers publish a decision offer as a real inline questionnaire for design/regular documents, or as a **proposed** ADR for another artifact kind. The questionnaire/source update, offer resolution, and attributed audit commit together. Acceptance remains the existing separate human review. Research offers cannot start work automatically. A writer edits the exact brief and presses Start research; the approved brief and stable claim are persisted first, and the Agent bridge receives the exact brief, original source version, and deterministic request key. Repeating a lost response recovers the same job. Existing offer/snapshot history is available through the full-export page hooks, including dismissed offers.

`tests/conversation.test.ts` runs fourteen cases against SQLite and fourteen against a real PostgreSQL instance when `STUDIO_TEST_POSTGRES_URL` is supplied, plus a Unicode byte-budget regression. The actual DecisionModels service/native adapter and installed generative SDK call real local HTTP fixtures; these are not live provider acceptance claims. Cases also distinguish native refusal/abstention/error/answered false, verify frozen independent profiles and explicit reanalysis, and prove an offline selected harness makes zero generative requests. Cases cover disabled capability, artifact/thread isolation, immutable model input and actual questionnaire publication, duplicate delivery, multi-writer observation deduplication, proposed ADR fallback, revocation during a provider request, fabricated quotation rejection with explicit reanalysis, changed discussion during a provider request, viewer/stale/revoked writer rejection, exact edited research brief and response-loss retry, atomic source/metadata rollback, and full history export. The research bridge is an explicit protocol fixture in this suite; the production Agent bridge and final application/browser integration are validated by their owning workflow.

The `ConversationCards` component uses the existing quiet compact interface and server capability response. It identifies AI proposals, source version and quotation, stale offers, actual analysis status/errors, explicit publication/research controls, and human review attribution. No screenshot of this isolated module is presented as evidence of final application wiring.
