# Managed native T3 with local CPU inference

The managed authoring path runs genuine pinned **T3 Code 0.1.5 → OpenCode 2.2.4 → the downloaded local CPU model**. The Studio model remains `t3-code / studioLocal / studio-local/<actual-local-model-id>`. It uses no AI Gateway, hosted model account, paid inference, existing CLI login, or substitute harness. The local CPU model is the provider inside the native T3 run.

`managedT3LanguageModel` receives the real SDK CPU model instance, Store, private ObjectStore, an artifact ID, a 32-byte server-only encryption key, and the pinned tools directory. `managedT3ToolsPresent` is a catalog presence check; every executable's exact pinned SHA-256 is checked before execution. The controlled installer is `node packages/studio/scripts/install-native-t3-tools.mjs /opt/studio-native-tools`; inference never downloads or updates tools. The installer includes both MIT licenses and the public T3 runtime resources.

Native processes run as the container's fresh service account. The runtime refuses existing Codex/Claude/OpenCode account directories without reading them: native T3's telemetry identity discovery probes the account home even with telemetry disabled. No `HOME`, `home`, or `CODEX_HOME` override is used. Native CLI commands receive only fixed paths, fixed arguments and a small environment with private XDG directories. No application/provider credentials are forwarded.

Each native state has its own empty workspace, native SQLite databases and native authentication. Standard native pairing-code approval plus OAuth PKCE grants only `orchestration:read`, `orchestration:operate`, and the **Supervised / approval-required** ceiling. Native provider/project/model capabilities are admitted through the existing strict Studio adapter before a turn. Launches explicitly request Supervised mode and stable request identity; every accepted readback checks the exact project, provider, model, thread, run and mode. The adapter never answers a native permission request.

OpenCode connects to an authenticated loopback CPU endpoint whose token is freshly generated by the server. The text-only provider refuses required native tool choices and never emits native OpenCode tool calls. Studio's separately advertised read-only server tools remain available through the existing JSON envelope and actual AI SDK orchestration. The CPU decoder constrains that envelope or the requested structured schema. The host recognizes only the exact complete server-generated native launch payload, presents its conversation in its original roles, and preserves all surrounding native context, instructions, tool declarations, response format and untrusted tool-result data. It does not select content by artifact substrings or discard source messages.

The managed loopback configuration is constructed inside this runtime. Remote endpoint validation still requires production HTTPS; no general endpoint safety rule is relaxed.

## Recovery and retirement

A SQL lease holds one owner per artifact/request/profile state. Project locking and current artifact existence checks precede the native state lock. Heartbeats renew ownership; lease failure aborts local inference and stops the fixed native process groups. A process-wide bounded queue admits one native runtime at a time per backend process.

All native processes stop before a snapshot. The archive contains bounded program-owned native state, SQLite databases and their quiesced journals, and the same native MCP session; it excludes executable installations, caches, logs and workspace files. AES-256-GCM authenticates the compressed archive and binds it to its stable artifact/request state ID. Only ciphertext enters the private ObjectStore. SQL atomically publishes its immutable key/hash under the native lease and optional caller fence.

The initial checkpoint is durable before inference starts. A completed turn checkpoints again before returning. Recovery restores the same native session and request namespace. A crash after the initial checkpoint may repeat read-only inference: this is **at least once**, while existing application SQL publication fences remain authoritative. No exactly-once native execution claim is made.

State is limited to 1,000 files and 48 MiB uncompressed bytes. The updated actual smoke used 14 files / 1,293,816 bytes, including T3's 983,040-byte SQLite database and OpenCode's 299,008-byte database. Known T3 and OpenCode diagnostic log directories are excluded while SQLite databases and their journals remain intact. The state path must be stable across backend replicas, and the encryption key must remain available for the queue's recovery window. Corruption, key changes, unavailable assets or exhausted bounds fail visibly.

The retained SQL ledger has artifact/project scope without cascading foreign keys. This preserves the encrypted object pointer after artifact deletion. Minute maintenance must call `cleanupManagedT3Checkpoints(store, objects, limit)`: missing-artifact state and state idle for seven days retire under fencing; Blob deletion succeeds before the pointer is removed. Failed Blob cleanup retains its retryable ledger. Staged or superseded objects have separate durable cleanup intents. This hook requires no decryption key.

Native OAuth sessions last 30 days and have no public refresh grant. When restored owned metadata has fewer than five minutes remaining, the runtime retains its native databases/history, obtains a fresh explicitly Supervised session through native pairing approval and PKCE, revokes the known previous owned session, and durably checkpoints before inference. The new native request namespace can recompute read-only inference; SDK metadata reports `sessionRenewed` and `namespaceGeneration` and does not call that same-session replay. Invalid or revoked unexpired sessions fail closed rather than overriding a permission decision. Queue retention is one day, below the native credential and checkpoint windows.

## Actual verification

`verification/t3-managed-local.ts` uses the actual installed T3/OpenCode executables, the actual Qwen CPU model, AI SDK, SQLite Store and private disk ObjectStore inside a fresh-account Docker container limited to two CPUs / 2 GiB with external networking disabled. The full run made eight native CPU calls and one direct CPU comparison. It verifies arithmetic, encrypted stop/restore with native replay and no additional CPU inference, structured transport, an actual Studio SDK server-tool/result/history/final loop, and the real `generateTitleGoal` path for grocery intent and Pact's human approval requirement. The retained [receipt](studio-evidence/continuation/t3-local-native/managed-qwen.json) keeps the original serialized-prompt 6×7 failure (14), its direct-model comparison and corrected role-preserving native result (42). It also retains the initial omitted product name and the intermediate incorrect AI-approval wording before the generic actor-preservation instruction produced the correct human-approval goal.

The focused [renewal receipt](studio-evidence/continuation/t3-local-native/managed-renewal.json) records two actual native CPU calls, zero extra calls on same-session replay, and the explicitly renewed namespace's recomputation. Offline thread-ID subset assertions show the original native thread remains present and a second thread belongs to the new namespace. Set `STUDIO_T3_VERIFY_CASE=renewal` for this focused process check; the default runs the complete workflow. `native-t3-state.test.ts` runs on SQLite and, when `STUDIO_TEST_POSTGRES_URL` is supplied, independent PostgreSQL connections; the owner-run matrix passed 41 checks with one SQLite concurrency-case skip, including the native permission and SDK harness fixture suites.

These are small actual workflow cases, not general accuracy guarantees for a 0.5B model. Context remains bounded by the local model; oversized requests fail without context shifting or silently dropping source text. Full hosted acceptance remains a separate check.
