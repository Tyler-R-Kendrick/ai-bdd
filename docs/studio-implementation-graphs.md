# Versioned implementation graphs

The implementation graph follows the [public Chopin lifecycle](https://github.com/githubnext/chopin/blob/main/docs/implementation-lifecycle.md): ordered tasks with acceptance criteria, a dependency DAG, exact-version human approval, one logical implementation run, per-task blockers and pull requests, no-change completions, independent whole-graph review, and revision requests that release the source lock. This is an authored Studio domain, not vendored Chopin source.

`shared/implementation.ts` provides bounded request contracts. `ImplementationGraphs` persists definitions, runs, attributed events and idempotency receipts through the shared asynchronous SQL adapter. `planRevision` is the canonical artifact version; `graphVersion` identifies a replacement definition and `draftRevision` advances edits within a draft. Approval and claims check all three counters. A replacement draft does not supersede the earlier approved version until a person approves it, and claims always inspect the latest version. A successfully verified graph cannot be claimed again.

Source mutations and graph operations acquire the same project transaction lock. Repository authorization is checked again after waiting, followed by the artifact's implementation lock. The common artifact write guard rejects source mutations during an active run. A durable external queue hook also locks a queued/launching build before it receives its domain run. Approve/claim/report transaction variants allow a connector's queue state and a domain transition to commit together; standalone methods publish only after their own commit. Draft publication has a transaction variant so the model job receipt, graph and notification outbox share one commit.

Tasks start only after prerequisites complete. A queued task may record an early blocker without bypassing the start check. Completion requires a reported repository-scoped pull request or a non-empty no-change reason and evidence. PR state and checkout values are declarations by the reporting caller unless a connected adapter independently validates them. The domain does not turn a supplied GitHub URL, commit SHA or evidence string into a live-provider verification claim.

Every review must address every criterion of every task exactly once. The server rejects the claimant and prior task contributors as reviewers, using transport-derived human/agent identities. Failed criteria return the failed tasks and their transitive dependents to queued work. Passing review releases the graph lock, records the reviewer, and labels the run implemented; a run with at least one PR becomes delivered once every reported PR is merged. An all-no-change run remains implemented. Verification evidence is retained in durable history.

Revision requests keep the old graph approved and eligible only while it remains latest. Archiving preserves an active run and accepts its lifecycle reports; permanent artifact deletion cascades all sidecars. A private, transport-inaccessible interruption method lets connector lease cleanup release work after the original writer loses access. It preserves the original claimant, records an explicit system event, and uses the exact run ID so an old expiry callback cannot unlock a replacement run.

The Build plan modal uses task/criterion/dependency forms and a DAG view. It shows source revision, exact approval pointer, source lock, blockers, reported PRs, no-change rationale, machine build status, and independent review/history. Planner drafting is a durable request that produces an unapproved graph. The runtime disclosure preserves the default T3 choice; selecting Vercel/fx requires an explicit saved change. Private checkout details appear only to their owner through the machine adapter.
