# Actual single-affinity CPU regression

A CPU quota alone did not reproduce the hosted runtime's `availableParallelism() === 1`. The controlled comparison restricted both quota and actual affinity to one permitted CPU, using the exported production dependency closure, pinned Qwen/native binding, non-root Node 24, no network, a read-only filesystem, disposable `/tmp`, and the existing 2 GiB container limit. The actual inference subprocess reported one available CPU.

With the original fixed two-thread configuration, a complete synthetic input of 1,494 estimated tokens reached prefill and exceeded the unchanged 45-second model deadline without decoding. Changing only the runtime and generation/decision context thread counts to `Math.min(2, availableParallelism())` completed the same input in 10.651 seconds, including its first decoded token at 10.621 seconds. Five genuine native decision questions completed in 6.133 seconds with uncalibrated probability vectors and observed RSS below 1 GiB.

The genuine native App gate also passed all ten checks under actual one-CPU affinity: HTTP arithmetic, native T3/OpenCode, checkpoint lease release, process restart and another turn, saved blue/Start source facts, preserved document/ADR/thread, controlled OAuth-issued sessions, password refusal and graceful shutdown. Its three native CPU requests completed in 14.081, 14.200 and 12.469 seconds. This was a local production-closure test with a synthetic OAuth provider, rather than a hosted deployment or live identity check.

The new mandatory image fixture selects the first CPU actually permitted inside its container with `taskset`, verifies that the model subprocess inherits one available CPU, and checks real chat, schema-constrained JSON, complete-source prefill, balanced native predicates and consistent ordinal probability distributions within the original model budgets. The local execution of that fixture passed. `container-smoke.mjs` invokes it unconditionally, retaining its existing native App, schema, memory, offline and browser checks. Complete image CI and hosted acceptance remain separate gates.

The thread cap improves this measured execution failure. It does not improve all model answers: the explicit “Reply only with the numeral” arithmetic prompt returned `3` with both thread settings, including the long-context case after the fix. A new “Is the chosen color blue?” decision paraphrase also returned the wrong predicate value despite the existing “mention blue” predicate passing. Those failures remain recorded in the [aggregate receipt](single-affinity.json). The long regression workload is explicitly a throughput test, and ordinal checks establish probability consistency rather than general rubric accuracy. An initial private experimental runner incorrectly set its aggregate pass flag after completed inference despite failed arithmetic assertions; the receipt explicitly corrects that flag and preserves the failed per-case results.

No inference deadline, context size, schema, memory limit, source-preservation rule or admission policy changed. No Sandbox adapter was activated and no AI Gateway call was made.
