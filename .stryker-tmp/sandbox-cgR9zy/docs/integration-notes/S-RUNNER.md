# S-RUNNER integration notes

Owner: `packages/sdk/src/runner/`, `packages/sdk/test/runner/`, `packages/sdk/test/kit/`. No contract changes, no new dependencies, no VERIFY items.

## runner (`packages/sdk/src/runner/`)

`createRunner(deps: RunnerDeps): Runner` (SPEC 9). Everything arrives through `RunnerDeps`; the module imports only `../contracts/index.ts` and `../util/index.ts`. Files: `runner.ts` (scheduling and gates), `scenario.ts` (one scenario end to end, commit rule), `steps.ts` (the §9.5 pipeline, branches A to D), `confirm.ts` (confirm runs), `session.ts` (session setup, settle helpers, teardown), `observed.ts` (judge evidence and evidence capture), `stub.ts` (FIXTURE_REQUIRED stub), `support.ts`, `sync.ts` (FIFO semaphore), `types.ts`.

### Behavior the neighbours should know

- **Never rejects.** `runScenario` and `runAll` always return `ScenarioResult`s. Setup problems (unknown driver `CONFIG_INVALID`, `RECORDING_READ_ONLY` for `-u` in read-only mode, `POLICY_DENIED` start URL, session open failure, corrupt recording `RECORDING_CORRUPT`, abort `ABORTED`) give scenario status `error`, `ScenarioResult.error`, and all steps `skipped` (with step events). A pre-aborted signal gives `error`/`ABORTED` for every target (also for not-yet-started scenarios), in selection order.
- **Driver and sessions.** `scenario.driver ?? opts.driver ?? config.defaultDriver`. With `opts.sessionFactory` no driver lookup is needed; `session.driverId`/`driverVersion` pick the recordings directory and the driver major. A `{param}` the step does not define, and a missing `{secret}` (`SECRET_MISSING`), make `resolveValue` throw; whatever the actor or driver does with that exception, the step ends `error` with the recorded code.
- **Recording rules.** Prefix validity by `stepKey` plus `sha256Hex(normalizeForQuote(text))`, driver major mismatch invalidates, `-u` skips loading. `recording: 'none'` when nothing was characterized or healed, `'discarded'` when a pending recording existed but was not persisted (failed or inconclusive scenario, non read-write mode, unstable confirm, store refusing with `RECORDING_READ_ONLY`), otherwise the store's `created`/`updated`/`unchanged`. A characterization attempt that fails (judge fail, agent failure) counts as pending, so it reports `discarded`. A failed heal reports `none`. Every step has an entry in the pending recording (fixture steps without `act`/`check`), so the recording is index-aligned with the plan.
- **Heal.** The new program is `[replay's completed prefix] + [actor actions re-recorded]`, recorded against the observation taken before the replay started. In read-write mode only (the spec says so) the step's recording is replaced and `healCount` incremented; `healCount >= healThreshold` demotes to fuzzy `heal-threshold`. In other modes a heal still marks the recording pending (`discarded`) but skips the probe and re-recording work.
- **`--strict`** fails a diverged replay with `REPLAY_DIVERGED` (`details` = `{outcome, completedActions, detail?}`) **without calling the actor** (cheaper and keeps CI deterministic). `--strict` wins over `--no-agent`.
- **Actor `blocked`** (`ACT_BLOCKED`) is a `failed` step (SPEC C1/C2: "otherwise failed"); the error code tells why. `blocked` steps come only from branch B.
- **`@fuzzy` / `subjective` override a deterministic recording** (author intent wins; the recording itself is left untouched). `@fuzzy` is recognised as the scenario tag `@fuzzy` (S-PLAN stores it with the at sign); a bare `fuzzy` tag is accepted too.
- **Inconclusive does not halt** the scenario (SPEC only skips after failed, blocked and error); later steps still run, scenario status is `inconclusive`.
- **Cleanup/close ordering.** SPEC lists confirm runs before step 5 "cleanup". The runner runs the fixture cleanups (reverse order) and closes the main session *before* the confirm runs, so a scenario never holds two sessions (keeps `maxSessions` and `exclusiveResource` honest and avoids fixture state clashes). A failing cleanup or close is a `log` warn event, not a status change.
- **Gates.** `runScenario` itself takes the exclusive-resource semaphore and then the per-driver `maxSessions` semaphore (fixed order, no deadlock), so concurrent direct callers (Playwright Test workers sharing a runner) are covered too. `runAll` is a worker pool over `runScenario`; results are in selection order. The hold spans the characterization, confirm runs and save.
- **Window rule / ring.** `before` is `replay.before` for replayed or healed run starts, otherwise a settled observation taken before the run. A single settled observation is reused for the next check when nothing could have changed the page (any action or fixture invalidates it). The recorder's `replay.after` is **not** reused: `ReplayResult` does not report `settled`, and unsettled screens must never be judged.
- **Events.** `scenario-start` (after mode is known; also emitted just before `scenario-end` for setup errors), `step-start`/`step-end` for every step including skipped ones (no events for confirm-run steps), `scenario-end`, plus `log` events (fixture `ctx.log` as `debug`, `confirm run n/m` as `debug`, cleanup problems as `warn`). The runner also appends each of these events to `evidence.record(...)` in emission order (S-FACADE says the runner owns `events.jsonl`). Evidence write failures never affect a run.
- **Evidence artifacts** (best effort): the actor `transcript` ref is attached to its step; `then` steps and failed/error/inconclusive steps get an `observation` artifact of the settled `after` observation, and a `screenshot` only when the step was judged or did not pass **and** the screenshot is allowed (untainted, or masked on a driver with `maskingProven`, R-SE2/R-JU3).
- **Error text.** Every error payload placed in a result goes through `redactor.redact/redactJson` (R-SE1).
- **`ScenarioResult.error`** is the scenario-level error if there is one (setup, `CHARACTERIZATION_UNSTABLE`, abort, save failure), otherwise the first step error of the step status that decided the scenario status (so reporters can read one place). `confirm.reclassified` holds step keys. `CHARACTERIZATION_UNSTABLE.details = {steps: [{stepKey, status, code?}]}`.
- **FIXTURE_REQUIRED.** `details = {fixture: <camelCased name, <= 40 chars>, stub: <TypeScript FixtureDefinition skeleton>}`; param types are inferred from the step param values.
- **Judge input.** The runner builds `JudgeEvidence` itself (`observed.ts`: `renderTree(refs:false)`, redact, truncate with the `...[truncated]` marker to `judge.maxTreeChars`, screenshot gating) so it does not import a sibling implementation. It mirrors `judge/toJudgeEvidence`. X-INTEGRATOR may replace `observed.ts#toJudgeEvidence` by `import { toJudgeEvidence } from '../judge/index.ts'` (same signature) if a single implementation is preferred.
- **Recorder capabilities.** `recorder.toRecording(..., step, { capabilities: session.capabilities })` is called with the sixth argument proposed in `contracts-proposals/S-RECORDING.md` (the call is cast; five-argument recorders ignore it). If the proposal is rejected the runner change is one line in `steps.ts#rerecord`.
- **Prompt versions** stamped on recordings are local constants (`act-v1`, `checkgen-v1`, `judge-v1`, `support.ts#PROMPT_VERSIONS`).

### Integration findings (acceptance run against the real modules, 2026-10-10)

12 of 13 acceptance files pass with this runner. `tests/acceptance/m11-bug-after-recording.test.ts` fails, both times for reasons outside the runner:

1. *Heal after an unverified effect.* With flag `bug-upgrade-noop` the replay of "the customer confirms the upgrade" performs the click but the recorded effect (`Plan: Pro`, toast, ...) never appears, so the recorder returns `effect-unverified` and SPEC C1.3 says heal. The scripted `act-confirm-upgrade` rule then tries to click "Confirm" in a dialog that the click already closed, so the fake model throws `MODEL_NO_RULE` and the step is `error` (the test expects the scenario to reach `CHECK_FAILED` on "the plan changes to Pro"). Verified fix on the corpus side: a variant layer for the bug flows with `{"id": "act-confirm-noop", "purpose": "act", "when": {"stepText": "the customer confirms the upgrade"}, "respond": {"script": []}}` (agent says `done` at once). The step is then `healed`, the next step fails `CHECK_FAILED` with path `check`, zero judge and checkgen calls, recording discarded. The runner must not treat `effect-unverified` as a pass (R-CH7, red-team attack 5).
2. *`--audit` and the judge cache.* In "M11 --audit disagreement" the audited run's judge verdict is a cache hit (`cached: true`) of the characterization run's identical evidence, so the "always fails" rule is never consulted and no disagreement appears. The test needs its own empty `cacheDir` for the audited engine.

## Driver conformance kit (`packages/sdk/test/kit/`)

`driver-conformance.ts` exports `runDriverConformance(name, makeFactory, options?)` (vitest). `makeFactory({appUrl}) => DriverFactory | Promise<DriverFactory>`; a zero-argument function works. Options: `appUrl` (Acme origin; for the fake driver any allowlisted http origin such as `http://localhost:4173`), `testToken` (default `acme-test`), `adminPassword` (default `correct-horse-battery`), `allowHosts`, `slowMs` (default 1500). Without `appUrl` the app tests are skipped and the identity, capability and navigate-policy tests still run. Import it relatively, e.g. from a driver package test: `import { runDriverConformance } from '../../sdk/test/kit/driver-conformance.ts'`.

Covered: id/version/capabilities shape and `selfCheck`; session identity; `navigate` denial of `javascript:`, `data:`, `file:`, off-host (also uppercase and trailing dot) and credential URLs with the page unchanged afterwards; allowed navigation; `policy.denyVerbs` (expects `POLICY_DENIED`); observation shape (unique refs, parent refs, levels, `treeHash === util.treeHash(nodes)`, stable across repeated observes, changes with the page, `revision` increases); navigation landmarks; duplicate controls distinguishable by ancestors (`/forms/two`); pixels only on request (PNG bytes, matching sha256); `fill`/`click` effects; stale-ref and unknown-ref rejection (`STALE_REF`; `TARGET_NOT_FOUND` also accepted for never-issued refs); taint after a secret fill (value never in the tree, screenshot masked, taint outlives navigation, only literal fills do not taint); `busy` on `/slow` then `Report ready`; session isolation of state and taint; `request()` shared with the session, isolated across sessions, test token enforced.

Checked against: the in-memory `mini-acme-driver.ts` (kit self-test, with fault injection), the real `fakeDriver()` from `@ai-bdd/testing` and the real `playwright()` driver against `startAcmeApp` (ad hoc runs on 2026-10-10: all 32 app tests pass on both).
