# Durable cross-instance collaboration

`Collaboration` treats its Yjs room as a cache. `Store.documentState` seeds exactly one canonical document under the project lock. `Store.persistDoc` merges a candidate into the latest durable state inside that same lock, validates the actual merged editor schema/assets, and returns the committed state. Replacements also carry an expected version. Only that returned state reaches live peers.

The default transport is a SQL fan-out log shared by independently connected instances. Document and project notification metadata are appended through the existing asynchronous transaction context in the document's `onPersist` callback. A failed notification append rolls back the source revision rather than making an unpersisted edit visible. The log uses a transactional clock, so a later-committed transaction cannot be skipped by a high-water cursor. Sender echoes are suppressed. Retention gaps trigger canonical-state refresh and presence resynchronization, rather than replaying old source as truth.

WebSocket handlers attach a bounded input queue before awaiting authentication. Incoming frames are processed serially per room, with byte/frame/rate bounds; every outgoing binary or project-event frame awaits fresh session and membership checks. Slow recipients have bounded application and network queues and reconnect from SQL. A revoked passive reader receives no subsequent document frame once that fresh authorization check observes the revocation.

Awareness is transient and attributed by the authenticated server, including across instances. Forwarded identities owned by another connection are ignored rather than reassigned to the forwarding client. Honest large awareness echoes are accepted within a bounded envelope, while each connection may author only ten small presence identities. Instance death expires awareness through the protocol's usual timeout; durable documents and decisions remain in SQL.

Application startup must `await collab.initialize()` before reporting readiness, and shutdown must `await collab.close()` before closing the Store. This drains queued work and closes subscribers. PostgreSQL supports cross-instance operation; the local SQLite adapter deliberately retains its one-writer-per-volume boundary.

`collaboration-distributed.test.ts` exercises real PostgreSQL17 connections, two independent Fastify/WebSocket instances, canonical initial state, simultaneous edits, instance restart, awaited-auth frame buffering, thirteen honest protocol peers, server-owned attribution, passive revocation, and transactional outbox failure. It also verifies SQL-log rollback and sender suppression. Tests use explicit session-adapter fixtures; existing authentication and browser tests verify the complete application wiring separately.
