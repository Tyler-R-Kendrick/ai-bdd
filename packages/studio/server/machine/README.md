# Connected machines

A connected machine runs the operator's already installed ACP agent. Studio does not install an agent, copy its provider credentials, or accept an executable from a project. The connector treats approved briefs and source documents as quoted data. The agent has the operator's ordinary OS permissions; worktrees organize changes and are not an OS sandbox.

The account device dialog presents the fixed trust statement and requires an explicit acknowledgement. The server retains its version and acknowledgement timestamp with the device. An account token can obtain project assignments only where its own user currently has write access, using the existing repository authorization callback. A new assignment refreshes authorization before its SQL transaction and rechecks it under the project lock. Denied and unavailable authorization produce visible blocked statuses and no runnable assignment.

Download `/connector.js` as `studio-connector.mjs`. The first-party bundle includes its MCP dependencies and redistribution notices; it needs Node 22 or newer and Git. It contains no hosted database, identity, model or credential runtime. Run it with the pairing code from **My connected machines**, `STUDIO_API_URL`, `STUDIO_MACHINE_SCOPE=account`, the absolute `STUDIO_MACHINE_AGENT_COMMAND` and the actual ACP arguments in `STUDIO_MACHINE_AGENT_ARGS`. Supply a repeated `--checkout /absolute/repository/path` for every permitted repository. Alternatively `STUDIO_MACHINE_CHECKOUTS` accepts a JSON array of `{ "key": "stable-local-key", "path": "/absolute/repository/path" }`. At most sixteen distinct repositories are admitted. Duplicate repositories are rejected instead of choosing a checkout. The server receives repository/commit/branch and an opaque local key, never a filesystem path. No unchecked repository is cloned, and no GitHub token is handed from the server to the connector.

The one-time code expires after ten minutes. The connector saves the resulting credential privately with mode `0600`; later launches reuse it after the pairing-code variable is removed. `STUDIO_MACHINE_CREDENTIALS` chooses its file, and `STUDIO_MACHINE_STATE_DIR` chooses its private state directory. Each account assignment receives a distinct, derived project credential. It cannot authorize another project, impersonate another device owner or replace the account credential. Existing project-scoped pairings remain supported.

One account process polls the explicit assignments fairly. A database device lock serializes claims across its project assignments. Every claim and publication rechecks project membership, repository permission, parent device authority, generation and lease. Project administrators can revoke a project assignment without revoking another user's entire account device. A deleted project credential leaves a tombstone; reconnect never silently recreates that grant. Removing an explicit checkout pauses its assignments and interrupts their local work.

Account revocation first fences the parent authority and all derived credentials, then interrupts its projects and releases their graph locks. A process failure between those stages leaves a durable `revoking` intent. Maintenance calls `cleanupRevoked()` to finish it. The result cannot be relabeled as a human verification. Revoking a device does not grant authority to another device or user.

Manual investigations and approved implementation graphs run in a detached worktree at the exact sealed commit, preserving existing checkout edits. Build worktrees receive the approved generated build branch. Prototype worktrees additionally reject pushes and are removed when execution ends. Source fetches use only the operator-selected repository's existing `origin`. Screenshots must be PNG/JPEG/WebP inside that run's worktree, without symlinks, at most three distinct files and one MiB each.

The ACP client advertises no editor filesystem or terminal capability. Its default permission policy denies requests. `STUDIO_MACHINE_ALLOW_PERMISSIONS=read,search` explicitly grants only those ACP tool kinds, once per request. The run-scoped MCP bridge exposes approved source and typed evidence/lifecycle operations, with no arbitrary application endpoint or uploaded UI code. An investigation candidate is published only after the ACP turn ends successfully. A build uses separate implementer and fresh verifier sessions; the verifier token can submit only whole-graph review. These are attributed external observations and never create a passing server test run.

Transient transport failures reconnect with bounded exponential backoff. Heartbeats retry while a local turn continues, and stop it after the server rejects its lease or the contact budget expires. Reports are fsynced privately before transmission and replay only their idempotent receipts after restart. A manifest left during uncertain execution is reported as interrupted, without starting the agent again. Manual worktrees remain for inspection. A state-directory lock prevents simultaneous connectors; after a process crash, verify the old process has ended before removing that named lock. Ctrl-C stops the owned process group and attempts a bounded interruption report.

The build runs `node scripts/build-connector.mjs` after the application bundle. `registerConnectorDownload(app,{file})` serves only that fixed first-party bundle. App composition initializes account routes after the machine/checkouts/graph schemas, assigns the three fresh-machine authorization hooks to `accounts.assertCurrentMachine`, includes `accounts.otherWorkActive` in claim guards, and calls `accounts.cleanupRevoked` from durable maintenance.
