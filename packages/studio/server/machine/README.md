# Connected machines

A connected machine runs the operator's already installed ACP agent. Studio does not install an agent, copy its provider credentials, or accept an executable from a project. The connector treats approved briefs and source documents as quoted data. The agent has the operator's ordinary OS permissions; worktrees organize changes and are not an OS sandbox.

The account device dialog presents the fixed trust statement and requires an explicit acknowledgement. The server retains its version and acknowledgement timestamp with the device. An account token can obtain project assignments only where its own user currently has write access, using the existing repository authorization callback. A new assignment refreshes authorization before its SQL transaction and rechecks it under the project lock. Denied and unavailable authorization produce visible blocked statuses and no runnable assignment.

Download `/connector.js` as `studio-connector.mjs`. The first-party bundle includes its MCP dependencies and redistribution notices; it needs Node 22 or newer and Git. It contains no hosted database, identity, model or credential runtime. Run `node studio-connector.mjs --help` for the installed-agent, repository and service controls. `connect` defaults to account scope; the existing environment-only project-scoped invocation remains supported. Set the pairing code from **My connected machines** and `STUDIO_API_URL` in the environment for initial pairing.

```sh
node studio-connector.mjs connect --agent copilot --checkout /absolute/repository
node studio-connector.mjs connect --agent atomic --clone https://github.com/owner/repo
node studio-connector.mjs connect --clone-attached -- /absolute/other-acp-agent --acp
```

The presets select already installed `copilot --acp --stdio` and `atomic-acp`, matching their published stdio ACP contracts. They do not download an agent or sign in to a provider. A custom installed command follows `--`; the connector resolves its executable and existing first script argument to absolute paths before switching worktrees. Existing `STUDIO_MACHINE_AGENT_COMMAND` and JSON `STUDIO_MACHINE_AGENT_ARGS` remain supported. T3's documented interface is its thread/MCP adapter, available through Studio's T3 integration; it is not mislabeled as an ACP executable.

Supply repeated `--checkout` paths to register existing repositories. Alternatively `STUDIO_MACHINE_CHECKOUTS` accepts `{ "key": "stable-local-key", "path": "/absolute/repository/path" }` entries. Repeated `--clone https://github.com/owner/repo` explicitly permits individual managed clones. `--clone-attached` separately opts in to discovering and cloning repositories attached to the current account's projects where write and repository authorization are fresh. Unavailable authorization fails visibly; viewers, another principal's projects and revoked assignments do not supply clone authority. The authenticated catalogue admits at most sixteen distinct repositories and refuses broader catalogues rather than choosing silently. Discovery without eligible repositories can remain connected while waiting for an assignment.

Managed clones live in a private operator-owned directory beneath the connector state directory; `--managed-root` selects another explicit absolute private root. They use local Git authentication, no server token, shell, checkout, submodule recursion or project-supplied executable. An explicit checkout wins over a managed clone of the same repository. Existing clone origins and paths are checked before reuse. The connector never resets an operator's dirty checkout. At most sixteen distinct repositories are admitted, and duplicate explicit repositories are rejected. The server receives repository/commit/branch and an opaque local key, never a filesystem path. Removing the clone opt-in or checkout removes its registration; it does not delete retained Git data.

The one-time code expires after ten minutes. The connector saves the resulting credential privately with mode `0600`; later launches reuse it after the pairing-code variable is removed. New `connect` commands default to `$XDG_STATE_HOME/studio/connector/device.json` or `~/.local/state/studio/connector/device.json`; the legacy environment-only command keeps its existing working-directory default. `STUDIO_MACHINE_CREDENTIALS` and `STUDIO_MACHINE_STATE_DIR` override these locations. Each account assignment receives a distinct, derived project credential. It cannot authorize another project, impersonate another device owner or replace the account credential.

Add `--install-service` explicitly to `connect` to pair and install a user service instead of starting a foreground poll. Linux uses user systemd and macOS uses a LaunchAgent, at user login; Linux persistence after logout requires the operator's own systemd linger policy. Windows service installation is rejected visibly; its foreground connector remains available. `node studio-connector.mjs service status` checks that same profile and `service uninstall` stops and removes only its owned definition/bundle, retaining credentials, reports and repositories. Use the same origin/credential/state overrides for these commands. Installation copies the first-party portable bundle and writes a private configuration; no one-time pairing code or provider token is serialized into it or the service definition. Unexpected changed definitions are retained for review. Uncertain activation is retained for explicit status/uninstall rather than deleting a possibly live service. No background installation occurs by default.

One account process polls the explicit assignments fairly. A database device lock serializes claims across its project assignments. Every claim and publication rechecks project membership, repository permission, parent device authority, generation and lease. Project administrators can revoke a project assignment without revoking another user's entire account device. A deleted project credential leaves a tombstone; reconnect never silently recreates that grant. Removing an explicit checkout pauses its assignments and interrupts their local work.

Account revocation first fences the parent authority and all derived credentials, then interrupts its projects and releases their graph locks. A process failure between those stages leaves a durable `revoking` intent. Maintenance calls `cleanupRevoked()` to finish it. The result cannot be relabeled as a human verification. Revoking a device does not grant authority to another device or user.

Account-managed Planner launch is negotiated separately with `planner-assignments-v1`; an older server continues ordinary approved work without being mistaken for a Planner-capable server. The device polls only its registered repository metadata, claims a typed artifact/source/profile/epoch, and keeps its account credential on the device-control HTTP plane. Only the short-lived artifact token reaches the Planner WebSocket and activity reads; neither credential enters the ACP process environment. The selected remote provider/model describes configuration intent. An operator-controlled ACP model remains explicitly unknown rather than being presented as a verified T3/GPT selection.

Planner sessions run in a populated, nonpush worktree at the local registry's exact Git commit. They never use a managed clone's empty working directory or disturb a dirty operator checkout. The server decides idle from durable turn/question state; the connector renews at fifteen-second intervals and enforces token expiry independently of a stalled renewal request. Stop/revoke/idle abort the WebSocket and owned ACP process. Before claiming, the connector fsyncs a private receipt containing identity/epoch but no scoped token. After a crash or an uncertain claim response, reconnect submits only a same-epoch failure release; it does not repeat model execution. Normal release cleans its ephemeral worktree. Uncertain worktrees remain private for operator review.

Manual investigations and approved implementation graphs run in a detached worktree at the exact sealed commit, preserving existing checkout edits. Build worktrees receive the approved generated build branch. Prototype worktrees additionally reject pushes and are removed when execution ends. Source fetches use only the operator-selected repository's existing `origin`. Screenshots must be PNG/JPEG/WebP inside that run's worktree, without symlinks, at most three distinct files and one MiB each.

The ACP client advertises no editor filesystem or terminal capability. In a real interactive terminal, permission requests show the tool kind, title and bounded command/input, with control characters removed. Choose allow once, allow this kind in this ACP session, or deny. Blank answers, unknown kinds, non-TTY/service runs, cancellation and a sixty-second timeout deny. Session grants remain in that client's memory, never select an agent's persistent `allow_always` option, and do not carry into another client/principal/verifier. `STUDIO_MACHINE_ALLOW_PERMISSIONS=read,search` remains an explicit operator policy granting only those tool kinds once per request. Browser question answers are separate and cannot authorize a tool. The run-scoped MCP bridge exposes approved source and typed evidence/lifecycle operations, with no arbitrary application endpoint or uploaded UI code. An investigation candidate is published only after the ACP turn ends successfully. A build uses separate implementer and fresh verifier sessions; the verifier token can submit only whole-graph review. These are attributed external observations and never create a passing server test run.

Verification uses actual local Git clones, SQLite/PostgreSQL authorization, spawned ACP fixture processes, the built standalone connector, private service bootstrap, `systemd-analyze verify`, and independent plist parsing. OS service-manager lifecycle calls are exercised through a recording manager fixture, without installing a service on the verification host. These checks do not establish a live Copilot/Atomic provider login or a live macOS service session.

Transient transport failures reconnect with bounded exponential backoff. Heartbeats retry while a local turn continues, and stop it after the server rejects its lease or the contact budget expires. Reports are fsynced privately before transmission and replay only their idempotent receipts after restart. A manifest left during uncertain execution is reported as interrupted, without starting the agent again. Manual worktrees remain for inspection. A state-directory lock prevents simultaneous connectors; after a process crash, verify the old process has ended before removing that named lock. Ctrl-C stops the owned process group and attempts a bounded interruption report.

The build runs `node scripts/build-connector.mjs` after the application bundle. `registerConnectorDownload(app,{file})` serves only that fixed first-party bundle. App composition initializes account routes after the machine/checkouts/graph schemas, assigns the three fresh-machine authorization hooks to `accounts.assertCurrentMachine`, includes `accounts.otherWorkActive` in claim guards, and calls `accounts.cleanupRevoked` from durable maintenance.
