# Saved-source prototype suggestions

Prototype suggestions are disabled by default. Set `STUDIO_SPECULATIVE_SPIKES=1` and configure an explicit independent decision provider to enable them. The artifact's saved decision profile chooses native OpenAI Decisions, native Jev/TypeSafe, or an explicitly registered structured-generation model. Chat or `STUDIO_MODEL` configuration does not enable or select this classifier. A person must also enable prototype consent on their own connected machine. Disabling consent cancels queued and running prototypes through the investigation service.

Only a committed change to a meaningful paragraph creates a candidate. Source writes, a SQL debounce lane, and a durable job outbox commit together. Dispatch happens after the outer database transaction releases its connection. Updating the lane while its job is queued coalesces edits; the worker freezes the latest exact passage in a durable step receipt after the quiet period. No process-local timer owns admission.

The worker freezes the separate decision profile with the saved source candidate. It asks one server-authored boolean question about the exact paragraph through the central DecisionModels port, with a 15-second abort signal and no tools. This bounded paragraph assessment makes no whole-document coverage claim. A provider context limit produces an explicit skipped result rather than silently truncating the source. Native probability, reported confidence, provenance and evaluation ID remain in durable history. Abstention, refusal, errors and a genuine false answer stay distinct; only an answered true value can advance to an investigation. The deterministic prototype brief quotes the saved passage and requests measured behavior and limitations rather than inventing findings. Shared SQL limits classification to six checks per document and ten per person per hour. A completed external step can be retried after process death before its receipt commits; its stable provider idempotency key and frozen source remain the same.

A useful classification can only admit a disposable investigation after fresh checks of membership, exact source version and hash, implementation lock, live personal machine consent, and investigation queue limits. Admission and the durable job receipt commit atomically. Results remain measured evidence or unverified findings; classification never approves an implementation or creates acceptance-test success.

`tests/spikes.test.ts` exercises native decision HTTP contracts and the explicitly injected legacy structured SDK adapter on SQLite and PostgreSQL, frozen profile selection, uncertainty/refusal/outage preservation, plus consent, operator opt-in, coalescing, rate limits, source changes, revocation, duplicate delivery, and rollback. These fixtures do not claim validation against a live paid model or an actual T3 installation.
