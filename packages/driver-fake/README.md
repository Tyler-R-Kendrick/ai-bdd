# @ai-bdd/driver-fake

An in-memory driver for the fixture app. It is the default driver in CI:

```ts
import { fake } from '@ai-bdd/driver-fake';
fake({ modelPath: 'fixtures/app/model.json', fault: { duplicateForms: true } });
```

## What it models

`fixtures/app/model.json` is generated by `node fixtures/app/build-model.mjs` from
`fixtures/app/screens.mjs`, the same module the HTTP fixture app renders from. A parity test
asserts that the served HTML, parsed into a role tree, equals the model per screen.

Each screen has a route, nodes (role, name, test id, `visibleWhen`) and the node transitions
that mutate state (`dialog`, `action`, `toast`). Refs are `r<revision>-<n>` and every
observation bumps the revision, so refs are invalid after a new observation (F-E3 semantics).

## Fault injection

| Flag | Effect |
| --- | --- |
| `spinnerMs` | `/slow` stays unsettled for that long (drives `SCREEN_NOT_SETTLED`) |
| `flakyNode` | a node appears only after the second observation (drives heal/miss) |
| `secureField` | the login screen keeps its password field |
| `duplicateForms` | adds a second `Submit` button (drives `ACT_TARGET_AMBIGUOUS`) |

## Capabilities

`navigate`, `tap`, `type`, `typeSecret`, `press`, `select`, `check`, `scroll`, `hover`, `back`;
pixels, trees, `maskingProven: true`, `nativePredicates: false`, `maxSessions: 8`. `typeSecret`
taints the session, after which screenshots are withheld.
